# TP Alert 项目文档

> 原名 **SmsAlarm**，2026-10 起更名为 **TP Alert**（版本 2.0）。

## 1. 项目概览

TP Alert 是一个 Android 应用，用于监听短信类通知并在命中特定关键字后触发高优先级报警。
当前默认规则：当通知正文包含 `上海交警` 时触发报警。

### 1.1 设计目标

- 在不读取短信数据库（无需 `READ_SMS` / `RECEIVE_SMS` 权限）的前提下实现"短信提醒增强"。
- 使用通知监听能力，降低对短信权限的依赖。
- 命中后拉起前台报警服务，保证提醒的可感知性。
- 兼容 Android 12+ 对后台启动前台服务的限制（见 2.3）。

## 2. 功能说明

### 2.1 核心流程

1. 用户在主界面点击"启用监控"。
2. 应用检查并引导开启**通知监听权限**（`Settings > 通知使用权`），并处理 Android 13+ 的 `POST_NOTIFICATIONS` 运行时权限；若被永久拒绝，引导进入系统通知设置页手动开启。
3. 后台守护服务（`KeepAliveService`）启动，维持进程活性；用户从设置页返回时 `onResume` 会自动补齐守护服务。
4. `SmsNotificationListener` 接收新通知并做筛选：
   - 来源包名是否疑似短信应用（Google Messages / AOSP MMS / 包名含 `sms`）。
   - 通知是否是新消息（单条 key 去重）。
   - **合并提取正文**：`title` + `text` + `bigText` + `MessagingStyle 消息列表`，避免会话式通知把正文放在 `bigText`/`MessagingStyle` 而 `android.text` 只是摘要时漏报。
   - 文本是否包含关键字 `上海交警`。
   - 是否通过防抖窗口（默认 5 分钟，可在编辑模式配置 1–30 分钟）。
5. 命中后**调度精确闹钟**（`AlarmManager.setAlarmClock`，无需 `SCHEDULE_EXACT_ALARM` 权限、Doze 下仍准点），约 1 秒后触发 `AlarmTriggerReceiver`。
6. `AlarmTriggerReceiver` 在闹钟（前台豁免）场景下启动 `AlarmService`。
7. `AlarmService`：
   - 将**闹钟流（STREAM_ALARM）音量抬到最大**，并在报警停止后**还原为原值**（不碰音乐流）。
   - 请求音频焦点（`AUDIOFOCUS_GAIN_TRANSIENT`）。
   - 循环播放 `res/raw/alarm.mp3`。
   - 振动（波形 0/700/500 循环）。
   - 在前台通知中提供"停止报警"按钮。
   - 达到配置的响铃时长（默认 10 分钟，可配置 1–30 分钟）后自动停止。

### 2.2 主要特性

- 单按钮监控开关，状态持久化（`MonitorConfig`）。
- **编辑模式**：滑杆配置防抖阈值（1–30 分钟）与响铃时长（1–30 分钟），退出编辑模式即生效。
- 兼容 Android 13+ 的通知权限申请，含被永久拒绝后的系统设置兜底。
- 报警服务支持手动停止与超时自动停止，停止时还原音量。
- 正文提取合并多种通知字段，降低漏报率。

### 2.3 关键设计：Android 12+ 后台启动前台服务限制

`SmsNotificationListener.onNotificationPosted` 属于**后台回调**：在 Android 12+（API 31+）上，
直接从回调里 `startForegroundService(AlarmService)` 会被系统抛
`ForegroundServiceStartNotAllowedException`，报警根本起不来（官方豁免名单不含通知监听回调，
且官方明确"已有前台服务运行仍视为后台"）。

解法：**精确闹钟中转**。命中后在监听器里用 `AlarmManager.setAlarmClock` 调度一个约 1 秒后的
闹钟；"应用调用精确闹钟完成用户请求的操作"是官方豁免场景之一，闹钟触发 `AlarmTriggerReceiver`
（普通广播接收器）时处于前台豁免上下文，再由它启动 `AlarmService`。此方案无需
`SCHEDULE_EXACT_ALARM` 权限，且 `setAlarmClock` 在 Doze 下仍会准点触发。

代价：系统状态栏会显示"下次闹钟"指示。若不需要，可改方案为 `setExactAndAllowWhileIdle` +
`USE_EXACT_ALARM`。

## 3. 架构与模块

### 3.1 模块分层

- **UI 层**：`MainActivity`
- **配置层**：`MonitorConfig`（SharedPreferences）
- **监听层**：`SmsNotificationListener`
- **调度层**：`AlarmTriggerReceiver`（精确闹钟中转）
- **执行层**：`AlarmService`、`KeepAliveService`

### 3.2 关键类职责

- `MainActivity`
  - 申请运行时权限（`POST_NOTIFICATIONS`）。
  - 引导用户进入通知监听设置页；永久拒绝时引导到系统通知设置。
  - 控制监控开关、编辑模式（防抖/响铃时长滑杆）、守护服务启停。
  - `onResume` 时补齐守护服务（用户从设置页返回的场景）。
- `MonitorConfig`
  - 读写监控开关、防抖分钟数、响铃时长分钟数。
- `SmsNotificationListener`
  - 来源过滤、正文合并提取、关键字匹配、去重与防抖。
  - 命中后调度精确闹钟（不直接启动前台服务）。
- `AlarmTriggerReceiver`
  - 接收精确闹钟触发，兜底检查监控开关后启动 `AlarmService`。
- `AlarmService`
  - 创建高优先级前台通知（含"停止报警"按钮）。
  - 保存并抬升闹钟流音量、申请音频焦点、循环播放报警音、振动。
  - 停止时还原音量；响应"停止报警"Action；超时自动停止。
- `KeepAliveService`
  - 以低优先级前台服务维持监控活性（`START_STICKY`）。

## 4. 权限与系统要求

### 4.1 Manifest 权限

- `POST_NOTIFICATIONS`
- `FOREGROUND_SERVICE`
- `FOREGROUND_SERVICE_MEDIA_PLAYBACK`
- `FOREGROUND_SERVICE_DATA_SYNC`
- `MODIFY_AUDIO_SETTINGS`
- `WAKE_LOCK`
- `VIBRATE`

不使用 `READ_SMS` / `RECEIVE_SMS`（Manifest 中已注释）。

### 4.2 用户手动配置

必须在系统设置中授予该应用**通知使用权（Notification access）**，否则监听服务无法接收通知。
Android 13+ 还需授予通知权限（`POST_NOTIFICATIONS`），否则报警前台通知（含"停止报警"按钮）
不可见。

## 5. 运行与构建

### 5.1 环境要求

- JDK 17（AGP 8.x 要求；旧文档的 JDK 11 已过时）
- Android SDK 34
- Android Studio（Hedgehog 或更新版本推荐）
- Gradle Wrapper 8.7

### 5.2 调试构建

```bash
./gradlew :app:assembleDebug
```

安装 APK（文件名带构建版本号）：

```bash
adb install -r app/build/outputs/apk/debug/TP-Alert-2.0.<versionCode>.apk
```

### 5.3 Release 构建与签名

`app/build.gradle` 从环境变量读取签名信息：

- `KEYSTORE_PASSWORD`
- `KEY_ALIAS`
- `KEY_PASSWORD`

签名**条件启用**：仅当 `../smsalarm.keystore` 存在且三个环境变量均非空时才配置签名；
否则 release 生成未签名包而不报错（debug 构建不受影响）。

```bash
./gradlew :app:assembleRelease
```

### 5.4 CI/CD

`.github/workflows/android.yml`（Build APK）在以下时机构建**已签名 release APK**：

- push 到 `master`
- 打 `v*` tag
- PR 到 `master`
- 手动 `workflow_dispatch`

要点：

- 使用 runner 自带 Android SDK（`android-actions/setup-android@v3` 已移除——它在当前 runner
  上尝试安装已被 Google 移除的 legacy `tools` 包而失败）。
- 仓库 Secrets 要求：`KEYSTORE_BASE64`、`KEYSTORE_PASSWORD`、`KEY_ALIAS`、`KEY_PASSWORD`。
- `KEYSTORE_BASE64` 未配置时跳过 keystore 解密并给出 warning（不中断构建）。
- 产物作为 artifact 上传，命名为 `app-release-2.0.<git 提交数>`。

## 6. 版本号与产物命名

- `versionCode`：由 Git 提交数推导（`git rev-list --count HEAD`）；Git 不可用（ZIP 下载无
  `.git`）或历史为空时回退到基于构建时间的值，**构建永不因 git 状态失败**。
- `versionName`：`2.0`。
- APK 文件名恒为 `TP-Alert-2.0.<versionCode>.apk`，每次构建产物唯一。
- CI artifact 名：`app-release-2.0.<git 提交数>`。

## 7. 配置项与可扩展点

### 7.1 当前可配置项（编辑模式滑杆）

- 防抖时长：1–30 分钟（默认 5）
- 响铃时长：1–30 分钟（默认 10）

### 7.2 当前硬编码项

- 关键字：`上海交警`
- 短信来源包名规则：Google Messages / AOSP MMS / 包名包含 `sms`

### 7.3 已知限制与建议的后续优化

- 音频焦点丢失（报警期间来电等）未处理，报警会持续播放。
- 关键字与包名白名单硬编码，建议暴露到设置页并支持多关键字/正则。
- 增加报警日志页（触发时间、来源应用、匹配文本摘要）。
- `KeepAliveService` 使用 `dataSync` 前台服务类型：若 targetSdk 升至 35，该类型有 6 小时运行
  上限，需更换类型或重新设计保活。
- 增加"仅耳机/蓝牙输出时报警"等音频策略。

## 8. 隐私与合规说明

- 本项目基于通知监听能力处理通知文本，不直接读取短信数据库。
- 当前代码未包含上传通知内容到外部服务器的逻辑。
- 若用于生产环境，请按目标地区法规补充隐私政策与用户授权说明。
